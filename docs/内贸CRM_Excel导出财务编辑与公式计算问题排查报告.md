# 内贸 CRM Excel 导出财务编辑与公式计算问题排查报告

> 排查范围：业绩订单 → 导出订单 → 导出数据  
> 约束：本轮只读代码与数据流分析，未改代码、未改库、未部署、未提交 Git。  
> 基准日期：以本地仓库实际代码为准。

---

## 结论先说

**不能 100% 做到「导出视觉格式完全不变，同时又让财务对多产品订单像普通表格一样随意矩形粘贴、向下填充加减公式」。**

限制在 Excel 自身：纵向合并单元格后，一个视觉格占多行，矩形粘贴 / 填充的目标区域行列数与选区不匹配，这是 Excel 原生行为，不是 SheetJS 写错保护导致。

在**尽量保留现有列顺序、合并观感、颜色样式、金额口径**的前提下，可以通过最小前端改动显著改善：

1. 金额写入真正的数值类型（`t:'n'`），避免空字符串文本参与运算触发 `#VALUE!`。
2. 合并区内「非首行」不要再写入 `""` 文本格，改为真正空白。
3. 若财务仍要在「订单级金额列」按产品行逐行填公式，需局部放宽合并策略（见第 7 节方案 B/C）。

## 1. 实际导出调用链

Excel **不是** PHP 服务端生成，而是浏览器端 SheetJS（`xlsx-js-style`）生成并下载。

```text
页面 GET  Order/exportindex
  → view: application/admin/view/order/exportindex.html
  → 引入 /js/xlsx.bundle.js（xlsx-js-style 1.2.0 / SheetJS 0.18.5）

用户点击 #exportBtn
  → exportBeautifiedExcel()          [exportindex.html ≈ L869–978]
  → POST Order/clientSearch          [page=1, limit=999999, keyword=当前筛选]
       Controller: Order::clientSearch()  [Order.php ≈ L3862–4087]
       （本路径不调用 OrderService 做 Excel 组装）
  → 取订单 id 列表
  → POST Order/getOrderItems         [order_ids=...]
       Controller: Order::getOrderItems() [Order.php ≈ L5979–6001]
       → buildOrderItemsSnapshotMap()    [Order.php ≈ L4145–4186]
       → 直查 crm_order_item（未走 OrderItem Model）
  → 前端把明细挂到 order.order_items
  → generateBeautifiedExcel(data)    [exportindex.html ≈ L981–1366]
       → aoa_to_sheet → !merges → 样式/数字格式 → writeFile
```

**澄清：**

| 用户点名文件 | 在本导出链路中的角色 |
|---|---|
| `exportindex.html` | **实际生成 Excel 的全部逻辑所在** |
| `Order.php` | 提供 `clientSearch` / `getOrderItems` 数据；`exportindex()` 仅渲染页面 |
| `OrderService.php` | **本导出链路不参与**（利润口径在下单/编辑时由 Service 写入主表，导出只读库字段） |
| `OrderItem.php` | **本导出链路不参与**；明细由 Controller 内 `Db::table('crm_order_item')` 查询 |

列表表格本身 `table.render` 的 `url` 是 `Order/index`（L1372），与「导出数据」按钮无关；导出走的是上面的 `clientSearch` + `getOrderItems`。

## 3. 已经确认的问题（代码级可证实）

### 3.1 多产品订单大量纵向合并，且合并范围包含金额列

当 `order_items.length > 1` 时，以下字段整列纵向合并（L1044–1051）：

**订单标识/文本类：**  
`order_no, team_name, at_user, order_time, country, cname, contact, invoice_type, split_remarks, bank_account, source_port, joint_person, client_company, product_name_summary, create_time_original, ut_time_original, old_crm_data, create_time, ut_time`

**订单级金额/比率类（对财务操作影响最大）：**  
`shipping_cost, invoice_amount, tax_amount, debugging_cost, sales_commission, amount_received, profit, margin_rate, owner_profit_rate, collaborator_profit_rate`

**不合并（产品行可独立编辑）的列：**  
`product_manager, product_name, spec_model, supplier, unit, qty, unit_price, total_price, purchase_price`（共 9 列）

全表约 38 列，合并约 29 列。视觉上「几行一单」完全符合财务描述。

### 3.2 合并区非首行被显式写成空字符串 `""`

L1110–1122：第二行及以后订单字段 `value = ''`。  
经 `aoa_to_sheet` 后，SheetJS 会生成 `{ t: 's', v: '' }`，**不是真正空白格**。

Excel 中：`数字 + ""`（空字符串文本）用 `+ - * /` 会得到 **`#VALUE!`**；`SUM()` 会忽略文本，表现不同。这与财务截图中的 `#VALUE!` **高度吻合**（机制已证实；具体哪条公式需人工复现确认）。

### 3.3 订单级金额取值使用 `\|\| ''`，把数值 `0` 也变成空串

L1075–1081 / L1185–1191：

```js
value = item[col.field] || '';
```

当 `shipping_cost / tax_amount / ... / profit` 等为 `0`、`null`、`undefined` 时，都会变成 `''`。  
随后 `type==='number' && value !== ''`（L1156）**跳过**数值转换 → 单元格保持文本空串或非数字文本。

### 3.4 产品金额使用 `\|\| 0`，空值被写成 0

L1142–1152：`qty / unit_price / total_price / purchase_price` 使用 `itemDetail.xxx || 0`，再 `parseFloat(...) || 0`。  
空/无法解析会被写成数字 `0`。这是**现有行为**；按本次要求「禁止未经确认把无法解析值转 0」，修复时应改为：可解析才写 number，否则真正空白，**不要**一律变 0。

### 3.5 占比列写入带 `%` 的文本

`formatPercentValue`（L810–818）返回如 `"100%"`、`"30%"`。  
列类型为 `percent`，后处理数字逻辑不会把它改成 `t:'n'`。  
若财务对「负责人占比 / 协同人占比」做加减乘除，会直接 `#VALUE!`（除非用 `VALUE`/`N` 等）。

### 3.6 数字格式后处理不完整

L1312–1321 仅在 `typeof v === 'string'` 且 `parseFloat` 成功时设 `t:'n'`。  
对已经是 `''` 的单元格：`continue` 前虽存在该格，但不会改成数值，也不会删除空串格。  
`z = '#,##0.00'` 只影响显示格式，**不能**把文本空串变成可运算数字。

### 3.7 导出未写工作表保护

已确认。财务「不能编辑公式」不是保护锁导致。

## 5. 合并单元格对编辑操作的具体影响

| 操作 | 不合并的产品金额列（数量/单价/售价/进价） | 已合并的订单级金额列（运费/税费/利润等） |
|---|---|---|
| 单击修改单个数字 | 一般正常 | 一般正常（改的是合并区左上角） |
| 同列向下拖填充公式 | 通常可用 | **易失败或结果错位**（多行共享一格） |
| 矩形区域复制粘贴 | 通常可用 | **易失败**：目标视觉行数与合并块尺寸冲突 |
| 在旁列对「每一产品行」引用本行订单运费做加减 | 产品列可算 | 只能稳定引用合并区首行；非首行地址行为依赖 Excel，且文件内还可能残留 `""` 文本格 |
| 筛选/排序 | 合并表本身就脆弱 | 更容易打乱「几行一单」视觉 |

**技术限制（必须向业务说清）：**  
只要保留「订单级字段纵向合并」，Excel 就无法提供与「纯明细平铺表」同等的逐行粘贴/填充体验。这不是 CRM 权限问题，是合并单元格的交互模型限制。

## 7. 最小修复方案及预计修改文件

**原则：** 不改列顺序、不改筛选/导出条件、不改库、不改利润计算口径、尽量保留颜色与「几行一单」观感。

### 方案 A（推荐先做，改动最小，视觉几乎不变）

**只改** `application/admin/view/order/exportindex.html` 的 `generateBeautifiedExcel()`（及少量辅助函数）。

1. **空值策略**  
   - 数字列：可 `parseFloat` 成功 → 写 number；`null/undefined/''` → 写 `null`（让 SheetJS 不生成空串文本格）；**不要**对无法解析的非空文本擅自改 0。  
   - 合并续行：订单字段不要写 `''`，写 `null`。  
2. **修正 `0` 被 `\|\| ''` / `\|\| 0` 吞掉**  
   - 用 `value == null || value === ''` 判断空；`0` 必须保留为数字 0。  
3. **生成后清扫**  
   - 遍历工作表，删除 `t==='s' && v===''` 的单元格（双保险）。  
4. **占比列（二选一，需业务拍板显示）**  
   - A1：仍显示 `100%` 文本（公式友好度低，格式最像现在）；  
   - A2：写入数值 `100`（或 `1`）并设百分比/`0"%"` 格式，便于运算（显示略有技术格式差异，需财务确认）。  
5. **合并范围可先不动**（仍合并金额列）→ 单格编辑 + 引用合并首行的公式会明显好转；跨合并块的矩形粘贴仍受 Excel 限制。

### 方案 B（在 A 基础上，显著改善「金额列逐行公式」）

从 `orderInfoColumns` 中**移出金额列**（运费、开票、税费、调试费、佣金、已收款、利润、利润率；占比按需）：

- 视觉：这些列不再合并，多产品订单会在每个产品行重复显示同一订单金额，或仅首行有值、其余空白。  
- 操作：可按行填充/粘贴公式。  
- 标识列（订单号、客户等）继续合并，整体仍像「几行一单」。

这是「最接近原布局」与「财务可算」之间的折中；**严格说改变了金额列的合并格式**，但列顺序/颜色/口径可变。

### 方案 C（财务计算友好，但偏离「合并观感」最多）

订单级金额在每个产品行**重复写入同一数值**且不合并。填充/粘贴最顺，但同一订单金额重复多次，需财务接受。

### 明确不建议

- 为省事删除全部合并。  
- 服务端改 PHP 再生成一套 Excel（本功能已是前端导出，重复建设）。  
- 修改数据库或利润公式口径。

### 预计修改文件

| 文件 | 是否需要 |
|---|---|
| `application/admin/view/order/exportindex.html` | **是（主改）** |
| `Order.php` / `OrderService.php` / `OrderItem.php` | 否（数据已够用） |
| 数据库 | 否 |

## 8. 修改后可能存在的兼容性风险

1. **合并策略若按方案 B/C 调整**：习惯「金额也合并成一块」的同事会觉得版面变了。  
2. **空串改真正空白**：依赖 `""` 当占位的旧手工宏可能行为变化（少见）。  
3. **不再把空产品金额写成 0**：合计/计数类公式从「含 0」变为「跳过空」，结果可能不同——这是刻意修正。  
4. **占比改数值格式**：旧对照表若按文本 `%` 匹配会受影响。  
5. **xlsx-js-style 样式**：继续依赖现有 bundle；勿换成无样式的 `xlsx.full.min.js`，否则表头蓝底等会丢。  
6. **超大导出**（`limit: 999999`）本身有浏览器内存风险，与本次类型修复正交，但合并+样式在大数据量时更卡。

## 9. Excel 人工测试清单

准备：导出至少 1 单多产品（≥3 行）+ 1 单单产品；财务常用客户端（Excel / WPS）各测。

1. 文件能打开；工作表未保护。  
2. 单产品行：直接改「销售单价」「售价合计」，保存再开仍在。  
3. 多产品行：只改不合并的「进价合计」，三行互不影响。  
4. 在空白列写 `=N{row}-O{row}`（售价合计−进价合计），多产品每一行都应出数字，不应 `#VALUE!`。  
5. 对合并的「估算运费」首行写 `=P{row}+1`（示例），应可计算。  
6. 故意引用合并块第二行地址做加减，记录 Excel 返回值（文档化限制）。  
7. 选中 3 个产品行的「销售单价」矩形粘贴三个数字 → 应成功。  
8. 选中 3 行去粘贴到「利润」合并列 → 预期仍可能失败（若仍合并）；方案 B/C 后应改善。  
9. `=TYPE(单元格)`：金额应为 `1`（数字）；修复前空续行可能为 `2`（文本）且 `LEN=0`。  
10. 运费/利润为 0 的订单：修复后应为数字 0，而不是空白文本。  
11. 占比列：若仍为 `100%` 文本，`=A+1` 应仍 `#VALUE!`；若改为数值格式，应可运算。  
12. 回归：筛选条件导出条数、列顺序、表头颜色、订单号合并观感与改前对比签字。

## 特别回答

### 能否真正做到「保持原有导出格式不变，同时让财务正常复制粘贴和使用加减公式」？

**不能承诺两者同时 100% 满足。**

| 诉求 | 能否满足 | 说明 |
|---|---|---|
| 列顺序/筛选/口径/颜色不变 | 能 | 仅前端写单元格方式调整即可 |
| 单格改数字、对产品金额列做加减公式 | 能（方案 A 后应明显改善） | 关键是数值类型 + 去掉 `""` 文本格 |
| 保留全部现有纵向合并（含金额列） | 能保留 | 但合并列上的矩形粘贴/逐行填充仍受 Excel 限制 |
| 在合并金额列上像普通明细表一样随意粘贴、向下拖公式 | **不能在「完全保留金额列合并」时做到** | 这是 Excel 合并单元格的固有限制 |
| `#VALUE!` | 方案 A 可消除「空串文本参与四则运算」这一类；不能消除用户公式写错或引用文本占比列造成的错误 | 需区分 |

**限制究竟在哪里？**

1. **Excel 合并模型**：纵向合并 = 多行共享一格，与「每行独立粘贴/填充」互斥。  
2. **当前实现把合并续行写成 `""` 文本**：放大了 `#VALUE!`，这一层可以修。  
3. **订单级金额与产品行一对多**：要「每行都能引用运费/利润做公式」，要么重复值，要么不合并金额列——与「金额也合并成一块」的版式存在业务冲突。

**建议对财务的话术：**  
「格式和列可以保持；数字会改成真正可算的数字，避免一算就 `#VALUE!`。多产品订单的订单号等仍合并。若还要在运费/利润这些整单字段上按产品行拖公式，需要允许这些金额列不再合并（或每行重复显示），否则是 Excel 合并表本身做不到，不是文件被锁。」

## 附录：问题归因对照（避免误判）

| 归因 | 是否成立 |
|---|---|
| 工作表保护导致不能编辑 | **不成立**（代码未开启） |
