## 结论先说

已按方案 A 完成前端最小修复：

1. **数字 `0` 不再被写成空字符串**，导出为真正数值 `0`。
2. **金额列**可解析值写为 Excel 数值（`t:'n'`）；空值写真正空白；非法非空文本保留原样，**不静默转 0**；千分位字符串（如 `1,200.00`）正确解析为 `1200`。
3. **多产品合并续行**订单字段改为 `null`（真正空白），并清扫残留 `""` 文本格；**未改** `mergeRanges` 生成逻辑，金额不会重复填到多个产品行。
4. **占比列**已确认库内为百分数口径（`100`=`100%`），改为数值 + 字面量 `%` 格式（`0"%"`），显示仍为 `100%` / `30%`，不会出现 `10000%`。

**仍未解决**：合并单元格上的矩形粘贴 / 按产品行向下拖公式（Excel 合并模型限制）。本轮未取消合并。

## 2. 修改前后代码差异

### 2.1 新增导出辅助函数（`formatPercentValue` 之后）

新增：

- `isEmptyExportValue(value)`：仅 `null` / `undefined` / `''` 视为空，**不把 `0` 当空**。
- `getExportFieldValue(source, field)`：安全取值并保留数字 `0`。
- `parseExportNumber(value)`：支持千分位；区分 empty / 合法数字 / 非法非空文本。
- `toExportPercentNumber(value, defaultValue)`：按库内百分数口径输出数值。

列表页 `formatPercentValue()` **未改**，表格展示仍显示 `100%` 文本。

### 2.2 数字 `0` 与空值（原 `|| ''` / `|| 0`）

**修改前：**

```javascript
value = item[col.field] || '';
// ...
value = itemDetail.qty || 0;
// ...
if (col.type === 'number' && value !== '') {
    value = parseFloat(value) || 0;
}
```

**修改后：**

```javascript
value = getExportFieldValue(item, col.field);
// ...
value = getExportFieldValue(itemDetail, 'qty');
// ...
if (col.type === 'number') {
    if (preserveEmpty) {
        value = null;
    } else {
        const parsed = parseExportNumber(value);
        if (parsed.ok) value = parsed.num;
        else if (parsed.empty) value = null;
        else value = parsed.raw; // 非法文本不转 0
    }
}
```

### 2.3 合并续行空字符串

**修改前：**

```javascript
value = ''; // 订单信息留空
preserveEmpty = true;
```

**修改后：**

```javascript
value = null; // 真正空白，避免 SheetJS 生成 t:'s', v:''
preserveEmpty = true;
```

`orderInfoColumns` 列表、`mergeRanges.push(...)` 起止行列计算 **未改动**。

### 2.4 占比字段

**存储口径确认（只读代码，未改库）：**

- `Order.php` 保存：`owner_profit_rate` / `collaborator_profit_rate` 为 `number_format($rate, 2, '.', '')`，且业务校验和为 `100`。
- 默认值：负责人 `100`，协同人 `0`。
- 显示函数 `formatRateDisplay` / 前端 `formatPercentValue` 均在数值后直接拼 `%`。
- 结论：**库内 `100` 表示 `100%`，不是 `1`。**

**修改前（导出）：** `formatPercentValue` → 文本 `"100%"`（`t:'s'`）。

**修改后（导出）：** 写数值 `100`，单元格格式 `z: '0"%"'`（字面量百分号）。

- 显示：仍为 `100%` / `30%`。
- 不会用 Excel 原生 `0%` 格式去格式化 `100`（否则会变成 `10000%`）。
- 公式可对数值直接加减（如 `100+30=130`），与库内百分数口径一致。

### 2.5 生成后清扫与数字格式

在数据行样式循环中：

1. 删除 `t==='s' && v===''` 的单元格（双保险）。
2. `type:'number'`：`#,##0.00`；用 `parseExportNumber` 处理字符串，避免 `parseFloat('1,200.00')===1`。
3. `type:'percent'`：设 `0"%"` 并保证 `t:'n'`。
4. 占比列右对齐（与金额列一致）。

## 6. 仍然存在的合并单元格限制

方案 A **保留**订单级金额列纵向合并，因此：

1. 多产品订单的运费/开票/税费/利润等仍是「多行共享一格」。
2. 在这些合并列上做矩形粘贴、按产品行向下拖填充公式，**仍可能失败或错位**——这是 Excel 合并模型限制，不是工作表保护。
3. 稳定做法：改合并区**首行**单元格；或在旁列引用首行地址做公式。
4. 若业务后续要求「金额列也能按产品行拖公式」，需进入排查报告中的**方案 B/C**（放宽金额列合并或每行重复值），本轮不做。

## 7. 财务需要进行的人工验证步骤

请用日常 Excel/WPS，从 CRM「业绩订单 → 导出订单 → 导出数据」导出真实文件后核对：

1. **打开文件**：能正常打开；工作表未保护。
2. **零值**：找运费/税费/利润为 `0` 的订单，单元格应为数字 `0`（可用 `=TYPE()` 期望为 `1`），不是空白文本。
3. **空值**：空金额格 `=LEN()` 为 `0` 且 `=ISTEXT()` 为假（或视为空白）。
4. **正常金额**：抽查几笔与系统列表一致。
5. **产品列公式**：在空白列对多产品行写 `=售价合计-进价合计`，每行应出数字，不应因空串出现 `#VALUE!`。
6. **合并金额首行**：对合并运费首行做 `=运费+1`，应可算。
7. **占比**：负责人/协同人显示仍为 `100%`/`30%` 这类，不应出现 `10000%`；可对占比做加减验证。
8. **合并粘贴限制（预期仍在）**：选 3 行数值粘贴到已合并的「利润」列，预期仍可能失败——属已知限制。
9. **版式回归**：列顺序、表头颜色、订单号合并观感、筛选导出条数与改前一致。
