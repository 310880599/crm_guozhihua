## 第四部分：订单客户关联实现

流程：`order_id` → 校验登录 → 查询 `crm_client_order`（`id` + `check_status=2` + (`at_user`=`当前用户` OR `pr_user`=`当前用户`)）→ `normalizeContact(contact)` → 未删除联系人匹配 → **distinct `leads_id` 必须恰好 1** → 加载 `crm_leads` → `canReadClientFollow`。

失败处理：

- 0 个匹配 / 客户不存在：拒绝，「无法定位订单对应客户…」
- >1 个 distinct leads_id：拒绝，「匹配到多个客户…」
- 无订单可见权：拒绝，「订单不存在或无权操作」
- 无客户跟进读权：拒绝，「您没有权限查看该客户跟进」

不信任前端 `leads_id`；不按客户名模糊；不取 find 第一条。

本地抽样：多笔审核通过订单可稳定落到同一 `leads_id`（方案 A：共享客户全部跟进）。

## 第五部分：身份快照实现

| 值 | 含义 |
|---|---|
| `owner` | 客户负责人（`crm_leads.pr_user` = 当前用户名） |
| `collaborator` | 客户协同人（`joint_person`） |
| `admin` | 仅超管 `admin_id=1` 且非负责人/协同人 |
| `''` | 历史未标记 → 展示「历史身份待确认」 |

优先级：`owner > collaborator > admin`。  
前端传入 `follow_role` **忽略**。  
写入入口：项目内用户跟进 INSERT 仅 `ClientFollowService::saveFollow`（`saveClientFollow` / `quickSaveFollow` / `comment` 转发均走此路径）→ **统一生效**。  
字段未就绪：拒绝写入并提示先执行库变更。

## 第九部分：数据库上线操作手册

1. **备份**：`mysqldump` 至少备份 `crm_comment`（建议整库）；确认可恢复。  
2. **确认环境**：实例、库名（如 `crmneimao`）、表名 `crm_comment`。  
3. **探测**：`SHOW COLUMNS FROM crm_comment LIKE 'follow_role';` 已存在且类型正确则跳过。  
4. **评估锁表**：当前为 **MyISAM**，ALTER 可能表级锁；低峰执行；勿认定「一定不锁表」。  
5. **执行**：人工执行 `sql/20260922_add_crm_comment_follow_role.sql`。  
6. **验证**：`SHOW COLUMNS FROM crm_comment LIKE 'follow_role';` → `varchar(20)` / `NOT NULL` / `DEFAULT ''`。  
7. **再部署代码**（顺序：先库后码；若码已先上，写入会拒绝直至字段就绪）。  
8. **功能验证**：我的订单写跟进/全部跟进；我的客户/批量跟进；转移后拒绝；历史记录「历史身份待确认」。  
9. **应用回滚**：优先回滚代码，**保留字段**。  
10. **库回滚**：仅评估后用 rollback SQL；`DROP COLUMN` 会永久丢失已写入身份快照。
