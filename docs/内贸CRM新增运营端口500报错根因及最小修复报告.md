# 内贸CRM新增运营端口500报错根因及最小修复报告

日期：2026-11-27  
范围：本地 `InquiryPort::add()` 新增运营端口 JSON `code=500` / `操作失败，请稍后重试`  
约束：未 commit / push / pull；未部署正式服务器；未改库结构；未取消事务与父来源行锁；未放宽权限与停用规则。

---

## 1. 真实错误原因

**根因不是 SQL、表引擎，也不是父来源校验本身。**

ThinkPHP `Controller::result()`（`think\traits\controller\Jump`）通过抛出 `think\exception\HttpResponseException`（继承 `RuntimeException`）结束请求并输出 JSON。

`InquiryPort::add()` 在事务 `try` 中调用 `$this->result(...)` 后，被宽泛的：

```php
} catch (\Throwable $e) {
    Db::rollback();
    return $this->result([], 500, '操作失败，请稍后重试');
}
```

**误吞**。于是：

1. 父来源检查失败、查重失败、插入成功后的成功响应，都会先抛出 `HttpResponseException`；
2. 被 `\Throwable` 捕获后统一改写为 `操作失败，请稍后重试`；
3. 浏览器看到 HTTP 200 + JSON `code=500`，与现象完全一致。

日志证据（`runtime/log/202611/27.log`，约 16:17:49）：

- `SELECT ... crm_inquiry ... FOR UPDATE`（父来源检查）通过；
- 查重通过；
- `INSERT INTO crm_inquiry_port ... '测试运营端口' ...` **已成功**；
- 无 SQL 异常；但前端仍收到 catch 文案。

库内对应记录：**`crm_inquiry_port.id=87`，`port_name=测试运营端口`，`inquiry_id=24`，`status=0`，`add_time=1795767469`** —— 属于“写库成功、响应被误改写”。

同类问题同步存在于同文件 `edit()` 的 `catch (\Throwable)`。

---

## 2. 异常发生阶段

| 阶段 | 实际行为 | 用户可见 |
|---|---|---|
| `parent_check` | 业务拒绝时本应返回明确文案 | 被吞成“操作失败，请稍后重试” |
| `dup_check` | 本应返回“运营端口已存在” | 同上 |
| `insert` + `commit` | **InnoDB 已提交成功** | 同上（最严重：成功当失败） |
| 真正 SQL/运行时异常 | 才应进入通用失败文案 | 修复后仍走此路径 |

异常类型（成功/业务拒绝被误捕时）：

- `think\exception\HttpResponseException`
- 文件：`thinkphp/library/traits/controller/Jump.php`（`result()` 抛出）
- 误捕位置：`application/admin/controller/InquiryPort.php` 原 `add()` catch

表引擎：**`crm_inquiry` / `crm_inquiry_port` 均为 InnoDB**（事务与 `FOR UPDATE` 可用，非引擎兼容问题）。

## 4. 修改前后行为

**修改前**

- 新增实际成功也会返回 `code=500` / `操作失败，请稍后重试`；
- 重复端口、停用父来源等明确业务拒绝也被改写成同一句；
- 用户重复点击会因“以为失败”再次提交；同名时库侧已有记录，但提示仍是通用失败。

**修改后**

- `result()` 正常结束请求，不再被事务 catch 吞掉；
- 成功：`code=200` / `操作成功`；
- 业务拒绝返回原有明确文案；
- 真实异常：rollback + `[inquiry_port_add]` / `[inquiry_port_edit]` 本地日志（仅 stage/异常类/消息/文件行号，不回传浏览器、不含凭据与联系方式）。

事务、父来源 `lock(true)`、`status=0` 启用校验、同父来源禁止重名 —— **全部保留**。
